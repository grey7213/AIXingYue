## 技术设计与复用

- 复用本仓库 `tools/backup_homer_production.py` / `tools/verify_homer_backup.py` 及已有 2026-09-07 清理记录。其他项目复用 tar/zstd、SQLite Online Backup、PostgreSQL pg_dump、MySQL/MariaDB 官方 dump；不引入新备份平台。
- 按实际 Docker mounts/compose、systemd WorkingDirectory、Nginx root/proxy 和本地部署记录建立项目映射，不按目录名猜测。
- 惑梦沿用 `E:/homer-backups/`。其他项目备份统一 `E:/server-backups/server-20261002/` 下独立目录，附本地源码映射和恢复说明；不写入本地源码树或同步盘。
- 数据库快照单独校验；文件在线备份记录时间跨度与一致性局限，发现 tar 文件变化则重试/快照，不能把失败当成功。
- 新完整恢复点取代旧分散备份。只删除清单中经过分类且不被运行进程、容器、符号链接引用的旧 release、备份和副本；保留当前版本和独有导入/安全资料。业务聊天、角色、网盘文件、数据库/WAL、当前 APK 发布文件不属于垃圾。
- Docker 只清理未使用构建缓存及确认不需要的旧镜像；不使用 `docker system prune --volumes`，不删除业务 volume。镜像至少保留当前运行版本；无外部仓库的本地镜像先导出备份。
- 日志保留最近 7 天及必要的体积上限，不删除当前日志。所有清理完成后复核健康和可恢复材料。
