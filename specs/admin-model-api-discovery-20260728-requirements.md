# 惑梦后台模型 API 自动发现与可用性检测需求

## 目标

- 管理员可以手动新增模型 API 节点，配置名称、协议、Base URL、API Key、温度和启用状态。
- 管理员可以从节点的 `/models` 自动读取候选模型并填入模型列表。
- 管理员可以对候选模型执行真实流式对话探测，只把确实返回有效正文的模型发布到用户模型选择器。
- 已保存节点在输入框留空时复用服务端旧 Key；任何管理员响应、公开接口、日志和前端状态都不得返回明文 Key。

## 用户流程

1. 管理员进入 `/admin.html` 的“模型配置”。
2. 点击“新增 API 节点”，填写节点信息。
3. 点击“读取模型目录”，后台请求该节点的 `/models`，自动填充模型列表。
4. 点击“检测全部模型”，后台以有限并发发送极短的真实流式对话请求。
5. 页面显示可用/不可用、耗时和脱敏错误；默认将模型列表替换为可用模型，管理员保存后用户即可选择并对话。
6. 管理员也可以跳过自动读取，手动维护模型列表，并检测当前填写的模型。

## 验收标准

- 新增管理员专用目录发现和模型探测接口；非管理员访问返回 403。
- OpenAI-compatible 节点从 `<base_url>/models` 读取目录，并用 `<base_url>/chat/completions`、`stream=true` 探测。
- Anthropic-compatible 节点支持 `/models` 目录及 `/messages`、`stream=true` 探测。
- 目录解析兼容常见 `data/models/result` 数组和字符串模型 ID，去重并限制最多 100 个候选。
- 单次服务端批量探测最多 12 个模型、最多 6 路并发、单模型有限超时；后台页面会自动分批覆盖最多 100 个候选。响应只返回模型名、状态、耗时和安全错误摘要。
- 现有预设可凭 `preset_id` 复用服务端 Key，新节点必须在本次请求提供 Key。
- 自动探测结束后后台可一键只保留可用模型，且至少一个可用模型时自动修正默认模型。
- `/console/api/web/model-presets` 只公开已保存且启用的模型，不包含 Base URL、API Key、探测请求或错误详情。
- 本地后端、前端语法、管理员 API 和真实 Chromium 桌面/390px 均通过。

## 非目标

- 不向普通用户开放 BYOK、自定义 Base URL 或 API Key。
- 不把一次探测成功当作永久 SLA，也不自动周期扫描上游。
- 不在探测失败时伪造回复或自动启用失败模型。
