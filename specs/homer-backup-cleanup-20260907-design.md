# 备份与清理实施设计

## 复用

沿用已有 `tools/backup_homer_production.py` 与 `tools/verify_homer_backup.py`。这是已实施备份流程的运维执行，不另建备份系统；先前 SQLite Online Backup、zstd 长窗口、scp 与恢复校验决策见 `homer-production-backup-20260824-design.md`。

## 执行顺序

1. 读取本机与生产状态，确认 DNS、SSH 主机身份、可用空间、服务和部署目录；仅输出元数据。
2. 用现成脚本全量备份，暂时保留服务器 staging。所有敏感配置仅进入本地归档，不打印内容。
3. 校验本地八个归档、数据库与关键文件；将压缩归档和恢复文档保留到服务器 root-only 的独立备份目录，核对哈希后移除本次临时明文快照。
4. 对旧备份生成精确清理清单。删除前重复检查路径、类型、大小/修改时间、主机身份、保留包校验和与本地验收证据；不跟随符号链接，不跨文件系统、不遍历未授权目录。
5. 执行已核验清单，记录删除体量与可用空间，复核线上库与服务。

## 保留策略

- 本地保留历史与本次完整备份。
- 服务器保留本次已验证完整压缩包；项目原有 backend/backups 的最近一个 SQLite 和一个前端源码恢复包继续保留。
- 仅删除被最新备份取代的、明确属于 Homer 的旧数据库快照、部署恢复包和本次临时文件；独有的迁移/安全材料保留。
- 输出证据写入 `output/backup-cleanup-20260907/` 与本地备份目录；稳定结论写入 SPEC 并按项目规则提交 Git。

## 初始实测

- `/` 总量 83,053,432,832 B，已用 31,421,288,448 B，可用 51,615,367,168 B（38%）。
- 本地 E 盘可用约 102 GB；当前 runtime `20260821-022929`。
- backend/dialogue/Nginx 均 active，内部 `/health` 为 OK。

## 验收发现的必要工具修正

- Windows 默认文本写入会生成 CRLF，Linux 的 `sha256sum -c` 把 CR 计入文件名。清单/manifest/恢复说明改为显式 LF，本次文本归一化后重新同步并打包；归档数据哈希保持不变。
- Cygwin scp 为下载文件设置显式 Everyone/Users ACL，父目录限权不足。备份工具创建目录先限权，传输结束后重置文件 ACL，再仅赋予当前 SID、SYSTEM、Administrators 完全控制；失败传输留下的文件也处理。数据库与对话归档标记为敏感。
- 验证使用真实 19 个本地路径的 SID 白名单检查、服务器原生 `sha256sum -c` 和 ZIP 逐成员 CRC/SHA-256，不额外重跑全量备份。
