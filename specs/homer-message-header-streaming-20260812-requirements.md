# 惑梦消息头与统一流式输出 Requirements

日期：2026-08-12

## 目标

按用户提供的对话 UI 恢复每条普通消息的轻量消息头，并确保所有会触发模型生成的对话动作都以真实流式增量显示。本文覆盖并替代 `homer-dialogue-message-menu-20260809-*` 中“普通状态完全隐藏消息头”的要求；长按/右键消息菜单继续保留。

## 功能范围

1. 消息头
   - 角色回复显示 `《角色名》`、角色卡版本和消息时间。
   - 用户输入显示用户名称和消息时间，不伪造角色版本。
   - 消息头提供帮助入口、更多操作入口和编辑入口。
   - “更多”打开现有 Homer 精确消息菜单；“编辑”继续复用 SillyTavern 原生编辑器。
   - 不恢复旧常驻操作条、原生 Swipe 箭头或候选计数。

2. 统一流式输出
   - 普通发送、续写、重写、下回续写和在最后一个候选上继续向右 Swipe 生成新候选，均固定使用流式请求。
   - 流式必须在生成结束前多次更新当前消息正文，不能只在结束后播放前端打字动画。
   - 已有候选之间的左右切换不伪装成模型流式生成。
   - 页面会话切换、设置重放或扩展设置更新后，Homer 模型连接仍保持流式开启。

3. 安全与兼容
   - 保持现有角色 Regex、TavernHelper、世界书、积分扣费和云同步链路。
   - 保持 RoleplayHub iframe `sandbox=allow-scripts` 且不增加 `allow-same-origin`。
   - 保持 `st-yuzi-phone` 停用，不恢复全局操作坞，不构建 APK。

## 验收标准

- `1440×900` 和 `390×844` Chromium 中消息头完整可见、无横向溢出。
- 角色消息头含角色名、非空版本、非空时间、帮助、更多和编辑；按钮作用于准确消息。
- 普通发送、续写、重写、下回续写、新 Swipe 五类生成均在结束前出现至少两次非空可见正文增量。
- 长按/右键菜单、编辑、删除、回溯、候选切换、云同步和角色脚本回归通过。
- console/page/network error 为 0，Yuzi JS/CSS 请求为 0。

## 非目标

- 不移除或替换现有长按/右键消息菜单。
- 不把版本号写入消息正文或云端消息内容。
- 不修改 `Tavo_主题效果_14G5y(1).thm`，不向公开仓库推送。
