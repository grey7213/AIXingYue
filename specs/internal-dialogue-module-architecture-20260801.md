# 惑梦内部对话模块架构规格（2026-08-01）

## 1. 目标与授权范围

- 目标工作区：`D:\网站\功能\惑梦-Homer-外部导入与角色卡兼容阶段备份-20260801`。
- 仅修改用户拥有的本地源码与隔离测试数据；不部署线上，不访问第三方账号或受保护数据。
- 对话页由惑梦前端控制；兼容运行时作为同源内部模块，不再成为浏览器顶层页面。
- 保留 Character Card V2/V3、世界书、Regex、卡内脚本、管理员扩展、RoleplayHub HTML/媒体和会话云同步能力。

## 2. 基线事实

1. `/app/chat.html` 当前只显示加载页，随后以 `location.replace()` 跳转到 `/dialogue-core/`。
2. `offline_dev_proxy.py` 把 `/dialogue-core/` 转发到本机 8091，同时公开代理 `/script.js`、`/scripts/*`、`/api/*` 等根路径。
3. 运行时响应只对 HTML 执行 `SillyTavern -> HomerDialogue` 字符串替换；JavaScript、模块名、全局对象和固定资源路径仍保留兼容标识。
4. `homer-bridge` 已负责角色导入、会话同步、预设悬浮球、历史会话、模型设置、Mod、权限和 RoleplayHub 兼容，适合作为内部模块桥接层继续使用。
5. 上游运行时采用 AGPL-3.0；修改版通过网络提供时必须保留许可证、修改说明和对应源码获取方式。

## 3. 目标调用链

```text
/app/chat.html（惑梦顶层页面）
  -> /console/api/web/dialogue/session（身份、角色、会话、短期桥接令牌）
  -> /module/dialogue/（同源内部 iframe 模块）
       -> 8091 内部运行时
       -> /api/homer/*（运行时到惑梦后端的受控桥接）
       -> /console/api/web/dialogue/*（模型、扩展、云同步）
```

## 4. 用户界面约束

- 浏览器地址始终保持 `/app/chat.html?...`，不跳转到内部模块地址。
- 浏览器标题、favicon、加载、错误、重试和返回路径全部由惑梦页面控制。
- 内部模块成功后通过 `postMessage` 报告 ready/title/error；顶层页面不读取账号 token，不向子模块发送密钥。
- 内部模块不能作为顶层页面使用；顶层导航请求重定向回 `/app/chat.html`。
- 对话功能区仍由现有 `homer-bridge` 生成，避免破坏复杂角色卡与扩展所需 DOM/事件语义。

## 5. 路由与资源边界

- 新公开内部挂载点：`/module/dialogue/`。
- 旧 `/dialogue-core/` 仅保留兼容重定向，不再承载页面。
- 运行时根资源与 API 通过模块前缀代理；HTML/JS/CSS 中的已知根绝对路径在代理响应中归一到模块前缀。
- 不向普通站点路由公开源码映射、Markdown、上游 README、开发目录或测试凭据。
- 代理移除上游 `Server`、`X-Powered-By` 等无业务意义的实现头；保留标准缓存、内容类型和安全头。

## 6. 运行时通信协议

消息统一使用 `homer:dialogue-host:v1`：

- `ready`：内部模块完成角色、会话和 UI 初始化。
- `title`：报告当前角色名，顶层设置为 `<角色名> · 惑梦`。
- `loading`：可选的阶段文本，不包含内部框架或版本信息。
- `error`：只传用户可读错误码和信息，不传堆栈、内部路径、令牌或响应体。
- `navigate`：请求返回历史/探索/登录等站内页面，顶层验证同源和允许路径后执行。

消息必须校验 `event.origin === location.origin` 和 `event.source === iframe.contentWindow`。

## 7. 权限与安全

- 卡内脚本和第三方扩展继续运行在现有受控上下文；扩展安装、更新、删除仍由后端管理员权限校验。
- 用户脚本不得获得顶层页面对象、localStorage 中的认证信息或任意站点导航能力。
- iframe 使用最小可行 `allow` 权限；不开放摄像头、麦克风、地理位置和支付。
- 日志、截图、HAR 和测试报告不得保存 Cookie、Authorization、桥接令牌、密码或 `secrets.json`。

## 8. 许可记录与用户界面

- 保留 `sillytavern-runtime/LICENSE`、上游版权和第三方扩展许可证。
- 2026-08-12 产品决定：站点导航、信息中心和其他普通用户页面不显示平台级“许可/开源许可与源码”或源码仓库入口，旧 `/app/open-source.html` 必须删除并返回 404。
- 第三方组件来源、固定版本、修改记录和许可风险继续保留在源码与内部规格中；隐藏用户界面不代表已取得闭源授权，也不消除 AGPL-3.0 或其他第三方许可义务。

## 9. 验收标准

1. 打开历史会话或角色卡后，顶层 URL 始终为 `/app/chat.html`。
2. 页面标题、加载、错误和导航无上游品牌、版本号或文档链接。
3. 直接顶层访问 `/module/dialogue/` 会返回到站内对话入口。
4. 常规 V3 卡、复杂卡和 RoleplayHub 卡在桌面 1440×900、手机 390×844 正常工作。
5. RoleplayHub 表单、23 条 Regex、Slash 变量桥接和媒体播放列表回归通过。
6. 预设悬浮球、历史切换、模型参数、Mod、世界书权限和云同步回归通过。
7. console error、page error、同源 network error 为 0，手机端无横向溢出。
8. 未出现凭据、Cookie、令牌或用户数据进入源码、日志、截图和报告。

## 10. 回滚

- 保留旧挂载点常量和启动参数的单点配置；若模块化入口回归失败，可临时把 `chat.js` 的 iframe 地址切回旧挂载点进行诊断。
- 不迁移或删除生产数据库；本次结构调整只改变前端入口、代理路径、桥接通信和平台级许可入口策略。
